# Use a specialist digital-avatar production chain

`$tuolin-avatar-video` uses Tuolin-owned knowledge grounding, confirmation gates, and run orchestration; Fish Audio supplies confirmed narration audio, HeyGen supplies presenter footage, HyperFrames authors the final visual composition, and FFmpeg performs media normalization, encoding, probing, and delivery validation. Pixelle-Video is reference material rather than a runtime dependency because its generic topic-to-video and ComfyUI/RunningHub workflow would require replacing the knowledge boundary, provider path, review model, and presenter-plus-evidence timeline; provider adapters remain replaceable without changing the confirmed business contracts.

Before any paid provider is called, the user jointly confirms one versioned production plan containing the communication strategy, complete verbatim narration, duration, presenter-presence intervals, product-evidence timeline, selected visual materials, bounded support-image batch, Fish Audio and HeyGen settings, surfaced high-risk claim notes, and estimated combined consumption. One confirmation locks the plan and authorizes exactly one initial attempt for every disclosed paid provider operation; changing scope or retrying requires renewed authorization.

Generated support visuals are permitted for abstract backgrounds, explanation, parameter layout, and transitions, but they never establish product facts. Product identity, parameters, test results, certifications, and real application or customer claims must use inspected official evidence exposed through the digital-avatar Agent's dedicated knowledge interface. A generated visual that depicts the product must be constrained by an inspected real product image and retain internal generation provenance. Because the user participates in and confirms the joint plan, the Agent adds no viewer-facing AI-generated or simulation label unless the user explicitly requests one; the generated visual still cannot substitute for evidence.

Paid support-image generation uses one bounded batch embedded in the complete production-plan confirmation rather than a separate prompt. The user reviews the provider, exact image count, purpose of each image, required inspected product references, and estimated consumption as part of that plan. Added images, changed purposes or references, provider changes, and paid retries require a new explicit authorization.

After plan confirmation, Fish Audio and the authorized support-image batch run in parallel when support images are required. Provider completion does not approve either result: the Agent combines full-audio listening and review of every generated image into one checkpoint and accepts one user response. HeyGen may use only the accepted audio, while HyperFrames may use only the accepted support-visual set. Rejected outputs and reasons remain in the run; replacement or regeneration requires new paid authorization and renewed combined review.

Fish Audio renders the complete confirmed narration before HeyGen runs. The user must listen to and explicitly accept that exact audio version; text approval or a short voice sample cannot authorize HeyGen, and regenerated audio loses the prior approval.

HeyGen then renders presenter footage from the accepted audio. HyperFrames may begin only after the user watches and explicitly accepts that exact HeyGen output; task completion is not approval, and regenerated presenter footage loses the prior approval.

HyperFrames is the preferred creative composition layer, but unavailability or execution failure automatically falls back to an FFmpeg template without repeating the interview or plan confirmation. The fallback preserves the confirmed narration, presenter footage, evidence and support visuals, timing, captions, and delivery specifications; it may simplify unsupported effects but cannot change facts, assets, or creative direction. No extra fallback confirmation is required because the final video still requires user acceptance, and delivery discloses the composition path used.

Rejected final renders may be revised and rerendered inside the same run when the change is limited to captions, title or parameter layout, BGM, transitions, or timing and placement of already accepted inputs. These packaging-only revisions clear only final-render acceptance and do not repeat the interview, plan approval, Fish Audio, or HeyGen. Changes to narration, provider outputs, facts, or evidence invalidate only the affected upstream contracts and follow the existing paid retry or changed-scope authorization rule; prior renders and rejection reasons remain versioned.

Every output defaults to time-synchronized, same-language captions burned into the video: English for English narration and Chinese for Chinese narration, without default bilingual treatment. The Agent owns timing, line breaks, styling, and platform-safe placement. Captions are omitted only when the user explicitly requests a caption-free output before production-plan confirmation.

For simplicity, outputs default to no BGM and the interview asks no music question. The Agent does not search, download, license, or select music; it includes BGM only when the user explicitly supplies a local track for packaging.

Rejected Fish Audio and HeyGen outputs remain as immutable versioned attempts in the same run. Every paid regeneration requires a new explicit user authorization, creates a new attempt instead of overwriting evidence, and invalidates all downstream approvals derived from the replaced version.
