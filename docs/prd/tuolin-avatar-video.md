# PRD：数字人口播视频 Agent（`$tuolin-avatar-video`）

## Problem Statement

拓霖已经具备正式产品知识卡、官方图片与视频素材，也已经决定使用 Fish Audio 生成克隆声音、使用 HeyGen 生成数字人口播原片。但现有 `$tuolin-video-workflow` 面向趋势研究、即梦镜头生成和镜头合并，`$tuolin-video-planner` 只交付镜头策划，两者都不适合承担“知识卡 → 逐字口播 → 克隆声音 → 数字人 → 产品证据与参数包装 → 最终竖屏成片”的完整责任。

如果把数字人口播能力塞入现有视频 Agent，会混合不同的知识接口、访谈逻辑、付费服务、确认状态和交付边界。此前多个下游 Agent 混用知识读取接口已经表现出效果差、耗时长的问题；继续复用共享投影还会让数字人口播任务读取不属于自己的上下文，增加检索噪声和错误机会。

用户需要的是一条高效、可审阅、可恢复的生产链，而不是一键黑盒或不断增加确认步骤的表单流程。用户会深度参与并确认内容，因此系统应把确认集中在真正影响方向、付费执行和产物质量的节点，避免逐句事实审批、重复消费确认和不必要的趋势研究。同时，系统必须阻止未确认音频、未确认数字人原片、错误产品素材或过期知识进入最终成片。

最终视频以30–90秒的9:16数字人口播为主，允许数字人暂时离开画面，由产品图、产品参数、应用信息或生成的辅助画面全屏接管。英文成片用于 YouTube Shorts；中文成片需要同时交付快手和抖音版本。视频生产与平台发布必须分离。

## Solution

新增必须由用户显式调用的独立 `$tuolin-avatar-video`。它拥有独立的 **Digital Avatar Video Knowledge Interface**、独立运行目录、独立状态机、独立供应商适配层和独立最终交付边界，不读取其他下游 Agent 的投影，也不扫描 raw 知识文件。

每个运行先进行一次只询问尚未明确的承重业务决策的 **Digital Avatar Video Interview**。访谈不搜索公开趋势，不让用户选择专业剪辑参数，在受众、观看理由、希望记住的信息、希望采取的行动、优先信息、排除内容、语言、平台、时长和数字人/产品证据关系达到充分后，生成一个完整、版本化的 **Confirmed Digital Avatar Production Plan** 候选。它同时包含策划、完整逐字稿、30–90秒目标时长、数字人出镜区间、产品证据时间线、已检查素材、生成辅助图片批次、字幕策略、Fish Audio/HeyGen设置和预计消耗。

用户一次确认完整方案，即同时锁定内容并授权其中已披露的首次付费生成。Fish Audio 与辅助图片批次并行执行；二者完成后，通过一次 **Digital Avatar Combined Input Review** 同时完成完整音频试听和全部生成图片验收。音频通过后，HeyGen 使用同一已确认音轨生成数字人原片；用户完整观看并确认后，HyperFrames 才能进行最终包装。

HyperFrames 是首选创意合成层，FFmpeg 负责媒体标准化、探测、编码和交付校验。如果 HyperFrames 不可用或失败，系统自动启用 **Deterministic Digital Avatar Composition Fallback**，使用 FFmpeg 模板实现同一已确认内容和时间线，不重新访谈或确认方案。最终成片默认烧录同语种字幕，默认无 BGM。英文运行交付一个 YouTube Shorts 文件；中文运行基于同一内容母版交付快手和抖音两个包装/编码版本。

Fish Audio、HeyGen 或生成图片未通过时，允许在同一运行内由用户明确授权重试；每次尝试、参数、费用、结果和拒绝原因不可变保存。最终包装未通过时，允许直接进行 **Packaging-Only Digital Avatar Revision**，只重渲染字幕、排版、转场或已确认素材的出现时机，不重复昂贵的上游生成。

用户完整观看并确认最终文件后生成 **Accepted Digital Avatar Delivery Pack**，任务结束。该 Agent 不登录、不上传、不发布到 YouTube、快手或抖音；后续发布由独立发布 Agent 负责。

## User Stories

1. 作为拓霖视频用户，我希望显式调用 `$tuolin-avatar-video`，以便明确启动数字人口播生产而不是其他视频流程。
2. 作为拓霖视频用户，我希望普通“做视频”请求不会被自动路由到数字人口播 Agent，以便系统不会替我猜测生产方式。
3. 作为现有视频工作流用户，我希望 `$tuolin-video-workflow` 保持原有即梦生产流程，以便新能力不会改变旧任务行为。
4. 作为视频策划用户，我希望 `$tuolin-video-planner` 继续只交付策划，以便它不会被数字人供应商状态污染。
5. 作为维护者，我希望数字人口播是独立消费者而不是旧 Agent 的模式开关，以便三条视频流程拥有清晰责任边界。
6. 作为用户，我希望每个数字人口播任务拥有独立运行目录，以便不同产品、语言和任务的文件不会混用。
7. 作为用户，我希望运行状态可以恢复，以便 Codex 会话中断后从当前确认点继续。
8. 作为用户，我希望恢复任务时系统先读取真实状态，以便不会根据聊天记忆重复或跳过阶段。
9. 作为维护者，我希望运行状态明确区分 active、blocked、rejected、completed 和 incomplete，以便草稿不会被误认为交付。
10. 作为审阅者，我希望所有关键修订和拒绝原因可追溯，以便了解最终成片如何形成。
11. 作为知识管理员，我希望数字人口播 Agent 只读取自己的 **Digital Avatar Video Knowledge Interface**，以便不受其他 Agent 上下文干扰。
12. 作为知识管理员，我希望数字人口播接口由同一正式知识源自动生成，以便不维护第二套产品事实。
13. 作为知识管理员，我希望数字人口播接口拥有独立 manifest、revision、产品索引、卡片投影和验证结果，以便职责可单独演进。
14. 作为知识管理员，我希望产品、平台、语言和运行只是接口内的任务筛选条件，以便不会产生一产品一接口或一任务一接口。
15. 作为知识管理员，我希望数字人口播接口声明 `raw_access=false`，以便下游不能绕过正式知识浏览 raw 文件。
16. 作为知识管理员，我希望知识库每次成功写入后自动刷新并验证数字人口播接口，以便用户不需要运行额外命令。
17. 作为知识管理员，我希望接口刷新失败时知识操作报告未完成，以便下游不会继续读取旧投影。
18. 作为用户，我希望缺失、过期或校验失败的数字人口播接口阻止创建或继续任务，以便系统不会猜测产品事实。
19. 作为维护者，我希望数字人口播接口失败不会破坏上一个已验证快照，以便故障可以安全恢复。
20. 作为审阅者，我希望每个运行固定创建时的接口 revision，以便同一成片不会混用不同版本知识。
21. 作为用户，我希望 Agent 从初始请求中提取已经说明的产品、受众、平台、语言和时长，以便不重复提问。
22. 作为用户，我希望口播策划前必须完成访谈，以便成片有清晰的业务目的。
23. 作为用户，我希望访谈一次只问一个会改变视频方向的问题，以便决策简单明确。
24. 作为用户，我希望每个问题只有一个带具体理由的推荐答案，以便不需要从固定创意分类中选择。
25. 作为用户，我希望普通“确认”只确认当前问题，以便不会意外批准后续内容或消费。
26. 作为用户，我希望访谈根据已确认答案动态决定下一问，以便流程不是固定问卷。
27. 作为用户，我希望访谈在信息充分后立即结束，以便不会为了形式继续提问。
28. 作为用户，我希望访谈确认目标受众，以便数字人的表达对象明确。
29. 作为用户，我希望访谈确认观众为什么愿意观看，以便口播不是产品说明书朗读。
30. 作为用户，我希望访谈确认希望观众记住的信息，以便内容有单一核心认知。
31. 作为用户，我希望访谈确认希望观众采取的行动，以便结尾符合业务目标。
32. 作为用户，我希望访谈确认优先产品信息，以便有限时长用于最重要内容。
33. 作为用户，我希望访谈确认排除内容，以便不出现不想表达的主题或素材。
34. 作为用户，我希望访谈确认数字人与产品证据的关系，以便口播和全屏产品画面协同。
35. 作为用户，我希望访谈确认一个30–90秒整数时长，以便生产不会依赖隐式默认。
36. 作为用户，我希望 Agent 不执行 YouTube、抖音或快手趋势扫描，以便快速进入与产品相关的策划。
37. 作为用户，我希望 Agent 不询问镜头数、运镜、字幕样式和转场等专业执行参数，以便由系统完成专业判断。
38. 作为用户，我希望英文任务面向9:16 YouTube Shorts，以便交付适配已确认英文渠道。
39. 作为用户，我希望中文任务面向快手和抖音，以便一次生产覆盖两个中文渠道。
40. 作为用户，我希望一个运行只生产一个语言版本，以便声音、字幕和节奏保持一致。
41. 作为中文操作者，我希望用中文完成英文任务访谈和审阅，以便不增加操作负担。
42. 作为用户，我希望 Agent 可以基于专属知识接口撰写完整逐字稿，以便不必提前准备脚本。
43. 作为用户，我希望也可以提供自己的完整逐字稿，以便保留我已经确定的表达。
44. 作为用户，我希望用户稿和 Agent 稿进入同一确认合同，以便后续供应商只有一个内容来源。
45. 作为用户，我希望事实检查只提示明显冲突和高风险参数、认证、测试、绝对性能或安全承诺，以便不会逐句重复审批。
46. 作为用户，我希望普通创意和营销表达由我最终确认，以便系统不会把我当作被动审查对象。
47. 作为审阅者，我希望发现的高风险冲突在方案确认前明确展示，以便用户可以修正或承担最终判断。
48. 作为用户，我希望 Fish Audio、HeyGen 和包装层都不能改写已确认逐字稿，以便口播内容始终一致。
49. 作为用户，我希望策划、逐字稿和数字人/产品证据时间线作为一个整体确认，以便时长和画面不会脱节。
50. 作为用户，我希望完整方案展示目标、叙事、逐字稿、时长、数字人出镜区间和产品证据区间，以便一次看清生产内容。
51. 作为用户，我希望完整方案展示所有将使用的正式图片和预览，以便确认实际画面而不是文件名。
52. 作为用户，我希望完整方案展示生成辅助图片的数量、用途、参考产品图、供应商和预计消耗，以便一次授权首次生成。
53. 作为用户，我希望完整方案展示 Fish Audio 和 HeyGen 的身份、关键设置和预计消耗，以便一次确认首次执行范围。
54. 作为用户，我希望一次方案确认同时锁定内容并授权所有已披露的首次付费操作，以便减少重复确认。
55. 作为用户，我希望方案任何受保护字段改变后整组确认失效，以便供应商不会使用过期输入。
56. 作为用户，我希望新增图片、改变用途、更换参考图或提高消费范围需要重新确认，以便授权不会无限扩张。
57. 作为用户，我希望每张候选正式图片在展示策划前经过像素级检查，以便文件名和元数据不会冒充视觉检查。
58. 作为用户，我希望图片检查覆盖主体、清晰度、构图、9:16裁切和近重复，以便素材适合竖屏成片。
59. 作为用户，我希望素材不足以支撑确认时长时流程明确阻止，以便不会用填充画面或意外重复蒙混过关。
60. 作为用户，我希望素材不足时可以选择缩短时长、明确允许重复或允许受约束模拟，以便由我决定取舍。
61. 作为审阅者，我希望产品身份、参数、测试、认证和真实应用声明只使用正式证据画面，以便生成图不会成为事实来源。
62. 作为用户，我希望 Agent 可以生成抽象背景、说明图、参数排版和转场画面，以便口播更易理解。
63. 作为用户，我希望包含产品的生成画面使用已检查真实产品图作为约束，以便不随意改变产品外观。
64. 作为审阅者，我希望生成画面不能虚构产品结构、性能、认证、测试、客户或应用证据，以便外部表达保持可靠。
65. 作为用户，我希望成片默认不自动添加“AI生成”或“示意”标签，以便系统尊重我已经参与并确认的方案。
66. 作为用户，我希望只有我明确要求时才添加生成画面标签，以便标注由业务需要决定。
67. 作为维护者，我希望运行内部仍保存生成来源，以便重做、审计和故障定位。
68. 作为用户，我希望 Fish Audio 与辅助图片并行生成，以便缩短等待时间。
69. 作为用户，我希望完整 Fish Audio 音轨必须实际生成，以便可以审查最终配音而不是短样本。
70. 作为用户，我希望在一次确认中完整试听音频并查看全部生成图片，以便减少串行确认步骤。
71. 作为用户，我希望音频审查覆盖发音、语速、停顿、语气和整体表达，以便 HeyGen 获得可靠输入。
72. 作为用户，我希望图片审查展示真实像素而不是提示词或任务状态，以便确认实际输出质量。
73. 作为用户，我希望一项输入未通过时另一项不会被误判为整组通过，以便联合审查保持准确。
74. 作为用户，我希望 HeyGen 只能消费已确认的完整 Fish Audio 音频，以便数字人口型与最终声音一致。
75. 作为用户，我希望首版使用 HeyGen 会员账户中的一个固定 public Avatar，以便快速验证生产链。
76. 作为品牌负责人，我希望固定 Avatar 使用版本化 ID，以便不同运行不会悄悄更换数字人。
77. 作为品牌负责人，我希望未来可以把固定 public Avatar 替换为自定义 Digital Twin，以便升级不需要重构工作流。
78. 作为审阅者，我希望会员权益与肖像、声音和素材授权分开记录，以便付费账户不会被误认为拥有所有权利。
79. 作为用户，我希望 HeyGen 完成后必须完整观看数字人原片，以便任务成功状态不会冒充质量通过。
80. 作为用户，我希望数字人审查覆盖口型、表情、动作、构图、身份和画面稳定性，以便问题在包装前发现。
81. 作为用户，我希望数字人原片确认后 HyperFrames 才开始包装，以便不会编辑一个待重做的上游结果。
82. 作为用户，我希望数字人可以暂时离开画面而旁白继续，以便产品图、参数和应用信息可以全屏展示。
83. 作为用户，我希望 Fish Audio、HeyGen 或辅助图片不通过时可以在同一运行重生成，以便不必重开全部任务。

101. 作为用户，我希望只有在方案确认前明确提出时才输出无烧录字幕版本，以便默认行为稳定。
102. 作为用户，我希望成片默认无 BGM，以便流程简单并避免寻找音乐的额外工作。
103. 作为用户，我希望 Agent 不搜索、下载、许可或选择音乐，以便 BGM 不形成新的耗时分支。
104. 作为用户，我希望主动提供本地音乐时仍可要求加入包装，以便特殊项目保留选择空间。
105. 作为用户，我希望中文快手和抖音版本共享同一口播音频、数字人原片、产品证据和核心时间线，以便不重复付费生产。
106. 作为用户，我希望快手和抖音版本只在安全区、结尾包装和技术编码上不同，以便内容保持一致。
107. 作为用户，我希望英文任务交付一个验证过的9:16 YouTube Shorts文件，以便可以交给发布流程。
108. 作为用户，我希望中文任务一次交付验证过的快手和抖音两个文件，以便无需自己转码。
109. 作为用户，我希望最终成片必须完整播放并确认，以便渲染成功状态不会被误认为交付完成。
110. 作为用户，我希望字幕、标题或参数排版、转场和已确认素材时机可以在同一运行快速修改，以便不重复声音和数字人生成。
111. 作为用户，我希望包装层修订只清除最终成片确认，以便上游已确认结果继续复用。
112. 作为用户，我希望修改逐字稿、声音、数字人原片、事实或证据时只回退受影响节点，以便依赖失效精确而高效。
113. 作为用户，我希望每个包装渲染版本和拒绝原因被保留，以便可以比较和恢复。
114. 作为用户，我希望最终接受后得到本地 **Accepted Digital Avatar Delivery Pack**，以便生产成果可以安全交接。
115. 作为用户，我希望数字人口播 Agent 不登录 YouTube、快手或抖音，以便平台凭据不进入生产流程。
116. 作为用户，我希望确认最终成片不等于授权发布，以便外部动作始终由单独流程确认。
117. 作为发布人员，我希望独立发布 Agent 只消费已确认交付包，以便不会上传草稿或被拒绝版本。
118. 作为维护者，我希望 API 凭据永远不写入知识接口、运行目录、日志或交付包，以便敏感信息受到保护。
119. 作为维护者，我希望所有外部调用使用脱敏日志和可注入伪供应商，以便测试不会产生真实费用或泄漏凭据。
120. 作为用户，我希望任何 blocked、mock、dry-run、stale 或 incomplete 状态都明确显示，以便不会把模拟结果当作真实成片。

## Implementation Decisions

- 新增独立 **Digital Avatar Video Entrypoint** `$tuolin-avatar-video`。它必须显式调用，不能由普通视频意图自动路由，也不能调用或复用其他视频 Agent 的运行状态。
- 新增独立 **Digital Avatar Video Knowledge Interface**，并注册到现有 Agent-specific interface 刷新事务。接口从正式知识源生成，拥有独立 revision、manifest、产品索引、允许卡片投影、搜索索引、正式图片与视频档案投影、风险策略和验证摘要。
- 数字人口播接口支持正式发布产品，首版按一个产品、一个语言版本、一个运行进行筛选。接口支持英文 YouTube Shorts，以及中文快手和抖音任务；画幅固定9:16，时长为30–90秒任意整数。
- 接口必须声明 `raw_access=false`。消费者只能通过专属读取 API 获得事实、风险、正式图片和已授权视频档案；不能读取其他 Agent 的投影、legacy context 或任意 raw 路径。
- 复用现有注册式知识接口刷新事务，但为数字人口播建立独立 builder、verifier 和读取 API。刷新采用隔离快照与原子切换；失败时保留上一个已验证接口并使当前知识写入报告 incomplete。
- 建立独立 **Digital Avatar Run Orchestrator** 深模块。它通过少量稳定操作封装运行创建、恢复、访谈回复、方案写入、方案确认、供应商提交、结果审查、合成、包装修订和最终接受。
- 状态机至少包含：访谈、可生成方案、等待方案确认、生成输入、等待联合输入验收、生成数字人、等待数字人验收、合成、等待最终验收、完成和明确阻塞状态。状态转换必须幂等，不能通过重复命令重复提交付费任务。
- 每个运行固定产品ID、接口 revision、语言、平台范围、30–90秒时长、9:16画幅、Fish voice ID、HeyGen avatar ID和当前方案 revision。凭据只从安全的本地配置或环境注入，不写入运行状态。
- 建立 **Digital Avatar Interview Core** 深模块，复用现有视频访谈的“一次一个承重问题、一个推荐和一个理由、每次答复后重算”的推理协议，但使用独立字段和独立状态。它不包含趋势搜索或固定创意分类。
- 访谈决策充分性覆盖受众、观看理由、核心记忆、期望行动、优先信息、排除内容、数字人/证据关系、平台、语言和具体时长。已在请求中明确的答案直接写入，不重复询问。
- 建立版本化 **Confirmed Digital Avatar Production Plan** schema。它包含传播策略、完整逐字稿、目标时长、连续时间线、数字人出镜区间、正式证据画面、生成辅助画面批次、字幕策略、供应商输入与关键设置、高风险提示、预计消耗和内容指纹。
- 用户提供的脚本与 Agent 起草脚本统一进入 **Confirmed Digital Avatar Narration**。确认前仅执行 **Digital Avatar High-Risk Claim Review**，检查明确知识冲突和高风险参数、认证、测试、绝对性能及安全承诺，不做逐句事实审批。
- 方案确认是唯一的首次内容与执行门禁。一次确认锁定完整方案，并授权其中已披露的辅助图片、Fish Audio和HeyGen各一次初始尝试；不存在单独的首次供应商付费确认。
- 任何方案受保护字段、供应商输入、辅助图片数量/用途/参考、预计消费范围的变化都会创建新方案 revision，并使旧执行授权失效。
- 建立 **Visual Material Inspector** 深模块，复用现有像素级检查能力，统一验证主体、清晰度、构图、9:16裁切、近重复、产品身份、权利、隐私和证据风险。所有进入方案的正式图片和产品参考图必须经过该模块。
- 区分 **Digital Avatar Evidence Visual** 与 **Generated Digital Avatar Support Visual**。事实证据只能来自专属接口中的已检查正式内容；生成内容只承担背景、解释、参数排版和转场，不得创建产品事实。
- 生成画面描绘产品时必须绑定已检查真实产品图作为视觉约束，并保存内部生成来源。默认不在观众画面中添加AI或示意标签，只有用户明确要求时才添加。
- 建立 **Provider Execution Coordinator** 深模块。它根据确认方案生成有界任务，防止重复提交，并把每次 Fish Audio、HeyGen和辅助图片调用写成不可变的 **Digital Avatar Provider Attempt**。
- Provider Attempt 记录供应商、输入 revision、输入指纹、关键设置、外部任务ID、提交时间、预计与实际消耗、输出引用、运行状态、用户审查结果和拒绝原因。它不保存秘密凭据。
- 使用可替换供应商适配接口隔离 Fish Audio、HeyGen和辅助图片生成。业务状态机只依赖标准化的提交、查询/取得结果、输出元数据和错误分类，不直接依赖供应商响应结构。
- Fish Audio 适配器只接收已确认逐字稿、固定 voice ID和确认设置，输出完整音频及可验证元数据。供应商不得重写文案。
- HeyGen 适配器只接收 **Confirmed Digital Avatar Narration Audio**、固定 versioned public avatar ID和确认设置，输出完整数字人原片及可验证元数据。
- 第一版要求从 HeyGen 会员账户选择一个固定 public Avatar。未来自定义 Digital Twin 只替换受控 avatar ID和授权元数据，不改变状态机或合成合同。
- 辅助图片适配器按 **Authorized Support-Visual Generation Batch** 提交精确数量、用途和参考。额外图片、用途变化或重生成必须获得新的显式授权。
- 初次方案确认后，Fish Audio 与辅助图片批次可以并行。两者完成后，系统生成一个 **Digital Avatar Combined Input Review**，在同一 Codex 确认视图中提供完整音频和所有生成图片。
- 联合输入验收的一次用户回复同时建立 **Confirmed Digital Avatar Narration Audio** 和 **Confirmed Digital Avatar Support-Visual Set**。任一输入被拒绝时不得进入依赖它的下游阶段。
- HeyGen完成不等于通过。系统必须在 Codex 中提供完整可播放原片，用户确认后建立 **Confirmed Digital Presenter Footage**，HyperFrames才可消费。
- 支持 **Authorized Digital Avatar Retry**。每次付费重试需要明确确认，创建新的 Provider Attempt，不覆盖旧输出，并按依赖图使受影响的音频、数字人、包装和交付确认失效。
- 建立 **Digital Avatar Composition Contract** 深模块，把确认方案、音频、数字人原片、证据画面、辅助画面和字幕转换成与实现无关的连续时间线。HyperFrames和FFmpeg保底都消费同一合同。
- HyperFrames适配器是首选创意包装执行器，负责数字人/全屏证据切换、产品图和参数信息布局、标题、字幕、转场和动画。其失败必须返回可分类错误，不能静默产生不完整交付。
- 建立 **Deterministic Digital Avatar Composition Fallback**。HyperFrames缺失或失败时自动使用FFmpeg模板执行同一合同，不增加用户确认。保底可以简化不支持的动画，但不能更改脚本、事实、素材或时间线含义。
- FFmpeg媒体模块负责输入探测、分辨率/帧率/像素格式/音频规格标准化、裁切与缩放、字幕烧录、拼接、平台编码和最终文件验证。所有调用必须使用确定参数并记录命令摘要与探测结果，但不记录秘密。
- 默认生成 **Digital Avatar Same-Language Burned Captions**。英文运行生成英文硬字幕，中文运行生成中文字幕；不默认生成双语。字幕时间来自确认逐字稿和最终音频时长，Agent负责断句、样式和平台安全区。
- 默认无BGM，访谈不询问音乐。系统不搜索、下载、许可或选择音乐；只有用户显式提供本地文件并要求使用时，才把它作为包装输入。
- 中文运行建立一个 **Chinese Digital Avatar Content Master**，复用同一确认音频、数字人原片、证据画面、辅助画面和核心时间线，派生快手与抖音两个 **Digital Avatar Platform Delivery Variant**。允许差异仅为安全区、结尾处理和技术编码。
- 英文运行输出一个9:16 YouTube Shorts交付文件。所有交付文件必须通过时长、尺寸、编码、音轨、可播放性和非空检查。
- 支持 **Packaging-Only Digital Avatar Revision**。字幕、标题/参数排版、用户提供的BGM、转场和已确认输入的时机变化，只创建新包装 revision并清除最终验收，不重新调用 Fish Audio 或 HeyGen。
- 包装修订如果触及逐字稿、音频、数字人原片、正式事实、证据画面或生成图片本身，必须根据依赖关系回退相应上游状态，并遵守新的付费授权规则。
- 最终验收必须展示完整可播放成片及验证摘要。用户确认后生成不可变 **Accepted Digital Avatar Delivery Pack**，包括交付视频、方案/供应商/合成 revision摘要、验证结果和实际使用的HyperFrames或FFmpeg路径。
- `$tuolin-avatar-video` 不保存平台凭据、不登录平台、不上传或发布内容。外部发布必须由独立发布消费者读取已接受交付包，并执行自己的发布确认。
- Codex对话是所有确认的主要审阅面。每个门禁必须直接展示足以决策的文本、图片、音频或视频；持久化文件只负责审计、恢复和下游执行，不能要求用户编辑JSON或运行内部脚本。
- 新 skill、来源插件副本和自然语言说明必须保持同步，并明确“显式调用、无趋势、30–90秒、英文YouTube Shorts、中文快手/抖音、默认字幕、默认无BGM、不发布”的边界。
- Pixelle-Video仅作为模块化供应商适配、任务历史和FFmpeg服务的设计参考，不作为依赖、子模块或运行时。不得继承其通用话题生成、单图数字人、RunningHub/ComfyUI工作流或自动营销文案。

## Testing Decisions

- 测试只断言用户可观察行为、持久化合同、外部适配边界和安全属性，不锁定私有函数、内部类名或实现顺序。
- 继续采用项目现有 `unittest`、临时项目目录、固定时间、JSON/Markdown产物检查、mock/patch和伪供应商模式。先例包括视频策划 Agent、视频策划专属接口、视频创建 Agent、Agent接口刷新和视频合并测试。
- 为 **Digital Avatar Video Knowledge Interface** 编写契约测试：独立目录与revision、多产品正式投影、允许卡型、`raw_access=false`、不依赖legacy context、预期卡验证和独立读取API。
- 为接口刷新事务编写集成测试：知识整理、更新、复核写回和视频档案发布后自动刷新；数字人口播接口失败时上游报告 incomplete，并保留上一已验证快照。
- 为显式调用边界编写测试：只有 `$tuolin-avatar-video` 创建数字人口播运行，普通“做视频”、`$tuolin-video-planner` 和 `$tuolin-video-workflow` 不会误入该状态机。
- 为运行创建编写参数化测试：正式产品、英语YouTube Shorts、中文快手/抖音、9:16、30–90秒整数、单语言和固定接口revision；拒绝未发布产品、错误平台、越界时长和无效接口。
- 为 **Digital Avatar Interview Core** 编写行为测试：跳过已知答案、一次一个待决项、一个推荐和理由、普通确认只作用当前问题、无趋势字段、决策充分后停止。
- 为高风险声明审查编写测试：明确参数冲突、认证、测试、绝对性能和安全承诺被提示；普通创意表达不触发逐句阻塞；任何审查结果都不能自动替代用户方案确认。
- 为生产方案 schema 编写测试：连续时间线、完整逐字稿、数字人/证据区间、素材指纹、字幕策略、供应商设置、预计消耗和辅助图片批次完整；任何缺失或冲突阻止确认。
- 为确认经济性编写状态机测试：一次方案确认同时授权所有已披露首次调用；不存在单独Fish、HeyGen或图片首次付费确认；范围变化和重试仍需要新授权。
- 为像素素材检查编写测试：缺失路径、未检查图片、错误产品、不可用9:16裁切、近重复、权利/隐私/证据风险阻止确认；用户批准的有意重复按合同保留。
- 为证据与生成画面边界编写测试：参数、认证、测试和真实案例不能只引用生成图；含产品生成图必须绑定真实检查图；不会自动添加观众可见AI标签。
- 为 **Provider Execution Coordinator** 编写确定性测试：同一确认和输入指纹只能提交一次；重复命令返回既有尝试而不产生第二次费用；不同revision创建新尝试。
- 为供应商适配器编写契约测试，使用本地伪响应覆盖成功、排队、失败、超时、畸形响应、缺失输出、任务ID不匹配和供应商拒绝，不在自动测试中调用真实付费API。
- 为Fish Audio适配器测试逐字输入不被改写、voice ID固定、完整音频存在、时长和媒体规格可探测，以及任何新音频版本不会继承旧确认。
- 为辅助图片批次测试精确数量、逐张用途、参考图绑定、并行执行、结果总览、部分失败和重新授权规则。
- 为 **Digital Avatar Combined Input Review** 测试一次回复同时确认完整音频和全部图片；缺少完整试听、缺少图片像素或任一拒绝不会错误推进HeyGen。
- 为HeyGen适配器测试只接受已确认音频、固定avatar revision、任务结果完整、媒体可探测，以及未确认或新生成原片不能进入HyperFrames。
- 为 Provider Attempt ledger 测试不可变版本、任务ID、费用、输出、审查结果、拒绝原因和依赖失效；拒绝结果不会被重试覆盖。
- 为凭据安全编写测试：API key、令牌、cookie和授权头不出现在状态、日志、异常文本、Markdown、JSON或交付包中。
- 为组合合同编写纯单元测试：数字人/证据切换、连续时间轴、字幕区间、素材引用和平台变体在HyperFrames与FFmpeg适配器之间保持一致。
- 为HyperFrames适配器编写mock集成测试：完整输入得到可探测渲染；插件缺失、失败或不完整输出自动触发FFmpeg保底；不会重复要求用户确认。
- 为FFmpeg保底编写媒体fixture测试：分辨率、帧率、像素格式、音频规格、裁切、字幕、拼接和时长正确；不支持动画被简化但内容顺序不变。
- 为字幕编写测试：英文音频只生成英文字幕，中文音频只生成中文字幕；默认硬字幕、无双语；显式取消字幕时才输出无硬字幕版本。
- 为无BGM默认编写测试：运行不询问、搜索、下载或生成音乐；只有显式提供且通过输入检查的本地文件进入包装。
- 为中文内容母版测试：快手和抖音复用同一音频、数字人、事实素材和核心时间线，只允许安全区、结尾和编码差异；不得产生第二次Fish或HeyGen调用。
- 为 **Packaging-Only Digital Avatar Revision** 编写依赖测试：字幕、排版、转场和时机只清除最终确认；逐字稿、音频、数字人或证据变化精确回退上游并要求必要授权。
- 为运行恢复和幂等性编写测试：在每个等待阶段中断后恢复，只展示当前待确认内容；已经完成的外部任务不会被重复提交。
- 为失败可见性编写测试：blocked、mock、dry-run、stale、rejected和incomplete均出现在结果与状态中，且不能生成 **Accepted Digital Avatar Delivery Pack**。
- 为最终交付编写测试：英文一个文件、中文两个文件；验证9:16、30–90秒、编码、音轨、字幕策略、可播放性、非空和实际合成路径摘要。
- 为发布边界编写测试：数字人口播运行不存在登录、上传、频道ID、发布文案或平台凭据字段；最终确认只生成本地交付包。
- 增加一条不产生真实费用的端到端 tracer：正式知识接口 → 完整请求跳过访谈 → 方案确认 → 伪Fish与伪图片并行 → 联合验收 → 伪HeyGen验收 → HyperFrames mock或FFmpeg保底 → 最终交付包。
- 自动测试完成后增加一次人工HITL验收：使用已授权Fish voice、选定HeyGen public Avatar和一项正式产品素材生成30–90秒真实样片，用户完整试听、查看图片、观看数字人和验收最终成片。真实调用前必须使用确认的首次执行范围。
- 全量回归必须证明 `$tuolin-video-workflow` 和 `$tuolin-video-planner` 的既有测试继续通过，且旧工作流不会加载HyperFrames数字人口播依赖。

## Out of Scope

- 将数字人口播做成 `$tuolin-video-workflow` 或 `$tuolin-video-planner` 的模式、阶段或隐藏路由。
- 修改或替换现有即梦视频工作流、视频策划工作流及其已确认交付边界。
- 公共YouTube、抖音、快手或其他平台趋势搜索。
- 在数字人口播 Agent 内整理、更新、复核或反向写入正式知识库。
- 读取任意 raw 知识文件、其他Agent接口、legacy任务context或未授权本地路径。
- 自动逐句事实审批、通用营销合规评分或替用户作最终内容判断。
- 支持30秒以下、90秒以上、横版、方形或多画幅成片。
- 英文YouTube Shorts与中文快手/抖音之外的平台，包括TikTok、Instagram Reels、LinkedIn或标准横版YouTube。
- 在同一运行中同时生产中文和英文，或用一个内容母版派生跨语言版本。
- 第一版强制创建HeyGen Custom Digital Twin、多Avatar轮换、按运行自动选择Avatar或迁移肖像权资料。
- 训练新的声音模型、取得声音/肖像授权或判断用户是否拥有第三方权利；首版只使用用户已授权并配置的voice和avatar。
- 供应商自动改写、翻译或扩写已确认逐字稿。
- 无人确认的自动付费重试、自动参数优化、自动重提或覆盖被拒绝结果。
- 把生成画面当作产品参数、认证、测试、客户案例、真实应用或性能证据。
- 默认添加观众可见的AI生成/示意标签；只有用户明确要求时才添加。
- 自动搜索、购买、许可、下载或推荐BGM，以及默认音乐混音流程。
- 平台发布、账号登录、上传、标题/描述/标签发布文案、排期、评论管理或数据分析。
- 把Pixelle-Video、RunningHub、ComfyUI或其通用话题生成管线作为运行时依赖。
- 保证视频爆款、播放量、询盘或转化结果。

## Further Notes

- 本PRD综合当前会话中已经逐项确认的决策，不再新增访谈。主要领域合同已经记录在ADR 0023、ADR 0025、ADR 0026和项目 `CONTEXT.md` 中；实现出现冲突时应优先保持这些已确认边界。
- 目标是提效而不是增加门禁。首版主路径只有四个生产确认点：完整方案与首次执行、完整音频与辅助图片联合验收、完整HeyGen原片验收、最终成片验收。范围变化和付费重试才增加确认。
- 最值得保持为深模块的部分是：专属知识投影、数字人口播运行编排、访谈与方案合同、供应商执行与不可变尝试账本、实现无关的组合时间线，以及FFmpeg媒体验证。它们应通过小而稳定的接口封装复杂行为，并可使用伪供应商独立测试。
- 实施前需要在本地安全配置已确定的Fish Audio voice ID/API凭据，以及HeyGen会员账户中选定的固定public Avatar ID/API凭据。凭据不得粘贴到PRD、知识卡、聊天日志或运行成果中。
- HyperFrames可用性不是用户决策。运行时检测失败后自动使用FFmpeg保底；最终交付摘要说明实际合成路径。
- 本地PRD仅定义要实现的产品和技术合同，不表示 `$tuolin-avatar-video`、专属知识接口或真实供应商调用已经存在。
