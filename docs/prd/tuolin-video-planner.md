# PRD：独立视频策划 Agent（`$tuolin-video-planner`）

## Problem Statement

现有 `$tuolin-video-workflow` 同时承担目标访谈、公开 YouTube 趋势搜索、素材检查、总体策划、逐镜头分镜、即梦任务、结果下载和视频合并。公开趋势搜索耗时较长，而部分用户只需要一份可靠、可直接执行的镜头策划，随后会自行选择视频生成工具并在剪辑软件中完成制作。继续使用完整流程会引入不需要的等待、确认步骤、供应商依赖和额度相关阶段。

同时，现有下游消费者实际共享通用知识读取投影。视频策划职责与完整视频生产职责不同，新 Agent 若继续复用 `video_creation` 接口，就会继承不属于它的产品限制、状态阶段和素材契约，也无法落实“每个 Agent 拥有独立知识读取接口”的目标架构。

## Solution

新增必须由用户显式调用的 `$tuolin-video-planner`。它通过一次只推进一个承重业务决策的动态访谈，理解产品、受众、问题场景、观看理由、核心记忆、期望行动、优先事实、排除内容和 AI 模拟边界；不执行公开趋势搜索，而是使用正式知识、已处理资产、用户答案和明确标注的模型策划推断，直接生成一份 9:16 的 **Production-Ready Shot Plan**。

该 Agent 支持知识接口中已发布的多个产品、YouTube Shorts 和 TikTok、中文或英文单语言版本，以及 15–90 秒的任意整数时长。它优先从已处理的视频资产目录和正式图片中选材，只有在正式应用已确认且真实素材不适用时才安排受约束的 AI 模拟。它输出镜头时间、用途、画面动作、素材及预览、运镜、转场、剪辑提示和可直接录音的逐字旁白。用户一次确认镜头与旁白后，系统自动生成完全一致的 SRT，不再设置 SRT 确认关卡。任务到此结束，不进入即梦、生成、下载、合并或发布。

新 Agent 使用独立、自动构建并验证的 **Video Planning Knowledge Interface**，固定每次运行创建时的接口 revision。知识库整理、更新或复核写回后，系统自动联动刷新所有已注册接口；本期只迁移新 Agent，现有消费者继续使用明确标记为 legacy 的共享接口，后续再逐个迁移。

## User Stories

1. 作为拓霖视频策划用户，我希望显式调用 `$tuolin-video-planner`，以便确定本次只需要镜头策划而不是完整视频生成。
2. 作为拓霖视频创作用户，我希望保留 `$tuolin-video-workflow`，以便需要即梦生成和合并时仍可使用原流程。
3. 作为用户，我希望普通“做视频”请求不会被自动路由，以便系统不会替我猜测应使用哪个 Agent。
4. 作为用户，我希望新 Agent 不搜索公开趋势，以便快速进入与本产品相关的策划工作。
5. 作为用户，我希望模型仍能主动推理钩子、叙事顺序和镜头表达，以便获得真正的策划建议而不是表单整理。
6. 作为审阅者，我希望模型策划推断与正式产品事实明确区分，以便判断哪些内容是创意判断、哪些内容有知识证据。
7. 作为知识管理员，我希望新 Agent 只读取自己的知识接口，以便它不会消费完整视频工作流或其他 Agent 的投影。
8. 作为知识管理员，我希望新接口由同一正式知识源自动生成，以便不产生第二套人工维护的产品事实。
9. 作为知识管理员，我希望新接口拥有独立 manifest、revision、卡片索引、视频资产目录、筛选规则和校验结果，以便职责变化不会影响其他 Agent。
10. 作为知识管理员，我希望知识整理完成后自动刷新新接口，以便用户不需要手动执行刷新命令。
11. 作为知识管理员，我希望接口刷新后自动验证本次写入应进入的投影，以便下游不会读取过期知识。
12. 作为知识管理员，我希望接口刷新或验证失败时知识操作报告未完成，以便失败不会被静默掩盖。
13. 作为维护者，我希望本次只迁移新 Agent，以便不扩大到所有旧 Agent 的高风险改造。
14. 作为维护者，我希望旧共享接口明确标记为 legacy，以便团队不会误报“全项目已完成接口隔离”。
15. 作为用户，我希望从新接口中选择任何已经正式发布的产品，以便新 Agent 不再写死石英纤维隔热带。
16. 作为用户，我希望产品未发布或接口不合格时任务明确阻止，以便系统不会通过扫描 raw 或猜测事实继续策划。
17. 作为用户，我希望一项任务支持 YouTube Shorts、TikTok 或同时声明两者，以便同一条 9:16 视频可按我的发布意图策划。
18. 作为用户，我希望所有方案固定为 9:16，以便首版不引入横版、方形或多画幅复杂度。
19. 作为后期人员，我希望 Agent 不负责平台安全区、字幕版式或 CTA 版式，以便这些视觉叠加由剪辑阶段统一处理。
20. 作为用户，我希望目标时长可以是 15–90 秒内任意整数，以便策划符合实际内容需求。
21. 作为用户，我希望未说明时长时 Agent 推荐 30 秒，以便快速完成常见短视频需求。
22. 作为用户，我希望镜头数量和每镜时长由模型动态决定，以便不被固定五秒一镜模板限制。
23. 作为用户，我希望每项任务只生成中文或英文一个语言版本，以便旁白时长和镜头节奏保持一致。
24. 作为中文操作者，我希望可以用中文访谈和审阅英文任务，以便英文成片不要求全程英文操作。
25. 作为外部观众，我希望英文产品名称和旁白使用正式知识接口确认的英文表达，以便不出现随意翻译的产品名。
26. 作为用户，我希望 Agent 先读取我已经说明的产品、受众、平台、语言和时长，以便不重复提问。
27. 作为用户，我希望访谈一次只问一个会改变视频方向的问题，以便可以专注做决策。
28. 作为用户，我希望每个问题只给一个有理由的推荐，以便避免从抽象创意分类中做选择。
29. 作为用户，我希望 Agent 对削弱观看理由、可信度或业务目标的选择提出具体挑战，以便策划不是被动迎合。
30. 作为用户，我希望访谈在决策充分后立即结束，以便不会为了“问得深入”继续收集无用信息。
31. 作为用户，我希望访谈直接生成完整逐镜头方案，以便不再确认一份重复的总体视频策划。
32. 作为用户，我希望希望观众采取的行动仍然被确认，以便结尾与业务目标一致。
33. 作为用户，我希望只有明确要求询价、联系或继续了解时才出现口播 CTA，以便旁白不自动变成销售话术。
34. 作为用户，我希望 Agent 不生成屏幕 CTA、联系方式排版或按钮设计，以便这些内容由后期处理。
35. 作为策划者，我希望 Agent 先查询轻量视频资产目录，以便无需一开始读取大量源视频文件。
36. 作为策划者，我希望只加载少量候选视频档案详情和代表帧，以便选材过程保持有界。
37. 作为策划者，我希望只有在代表资产不足以判断具体镜头时才生成低清预览，以便减少不必要的视频处理。
38. 作为知识管理员，我希望预览只来自正式授权的关键片段，以便下游不能遍历或扫描 raw 视频目录。
39. 作为知识管理员，我希望运行时通过不透明视频资产 ID、档案 revision 和片段边界访问源文件，以便路径移动和权限边界可控。
40. 作为用户，我希望每个视频候选显示真实内容摘要、代表帧、风险和可用能力，以便我理解 Agent 为什么选它。
41. 作为用户，我希望每个最终视频片段记录准确时间范围、原始来源、预览和镜头用途，以便我可以在剪辑软件中找到素材。
42. 作为用户，我希望真实可用视频片段优先于图片和 AI 模拟，以便成片尽可能使用可信的动态素材。
43. 作为用户，我希望真实图片在没有合适视频片段时作为直接素材或生成参考，以便产品外观保持准确。
44. 作为用户，我希望 AI 模拟只用于正式知识确认的应用场景，以便不虚构产品用途。
45. 作为审阅者，我希望每个 AI 模拟镜头明确标注为模拟，以便它不会被误解为真实客户现场或测试。
46. 作为审阅者，我希望出现具体产品的模拟镜头必须绑定真实产品图片，以便生成时不会凭空改变产品身份。
47. 作为审阅者，我希望没有可靠产品参考图时产品模拟镜头被阻止，以便系统不会发明产品外观。
48. 作为审阅者，我希望 AI 模拟不能作为真实客户案例、测试记录或性能证据，以便外部表达保持可信。
49. 作为用户，我希望只选择通过主体、构图、路径、授权和重复检查的素材，以便方案中的素材实际可用。
50. 作为用户，我希望处于复核状态的资产可以显示为候选但不能进入最终方案，以便风险对我可见又不会被误用。
51. 作为审阅者，我希望产品身份、客户隐私、测试含义、素材权利和声明风险在确认前清零，以便最终方案适合外用。
52. 作为用户，我希望原视频片段默认仅使用画面，以便现场声音、客户信息和版权声音不会进入方案。
53. 作为用户，我希望逐字旁白成为 Agent 唯一编写的声音内容，以便声音信息与镜头节奏可控。
54. 作为配音人员，我希望旁白是可以直接录音的逐字稿，以便不需要二次扩写表达要点。
55. 作为配音人员，我希望旁白按正常语速校验能在镜头时间内读完，以便录音不会挤压镜头节奏。
56. 作为用户，我希望每个镜头包含时间、目的、画面动作、素材、运镜、转场、剪辑提示和旁白，以便可以直接进入生成与剪辑。
57. 作为用户，我希望在确认前用自然语言删除、重排或修改镜头和旁白，以便不需要编辑 JSON。
58. 作为用户，我希望修改必须真正更新镜头文件并重新展示，以便聊天记录不能冒充成果修改。
59. 作为用户，我希望镜头、素材和旁白作为一个整体确认，以便相互依赖的时间关系不会分开锁定。
60. 作为用户，我希望确认旁白后自动生成 SRT，以便无需手工复制时间轴。
61. 作为用户，我希望 SRT 与确认旁白逐字一致，以便字幕不会成为第二套内容来源。
62. 作为用户，我希望 SRT 不需要再次确认，以便同一份文字不被重复审批。
63. 作为用户，我希望修改 SRT 文案被视为旁白修改，以便系统重新校验语速和镜头时间。
64. 作为用户，我希望每次策划创建独立运行目录，以便不同产品、语言和视频任务不会混用文件。
65. 作为用户，我希望运行保存访谈决定、状态、修改记录、素材检查和预览，以便中断后可以继续。
66. 作为用户，我希望交付包含 Markdown 和 JSON 镜头方案及 SRT，以便既能人工阅读又能被后续工具消费。
67. 作为用户，我希望运行目录不出现即梦 Prompt、任务、生成视频或合并结果，以便策划 Agent 不越界。
68. 作为用户，我希望已交付方案仍可在同一运行内继续修改，以便实际制作前可以微调。
69. 作为用户，我希望交付后修改创建新的编号修订版并保留旧版，以便历史结果可以审计和恢复。
70. 作为用户，我希望镜头时间或旁白改变时旧 SRT 自动失效，以便不会误用过期字幕。
71. 作为用户，我希望新版镜头与旁白重新确认后才生成新版 SRT，以便每个版本保持内部一致。
72. 作为用户，我希望每个运行固定创建时的知识接口 revision，以便同一方案不会混用不同版本的事实。
73. 作为用户，我希望知识库更新不会静默改写正在进行的策划，以便我的审阅对象保持稳定。
74. 作为审阅者，我希望最终确认前重新检查所选知识和资产是否撤销或实质变化，以便过期材料不能进入交付。
75. 作为用户，我希望发现实质知识变化时创建新策划运行，以便新旧事实不会在同一状态机中混合。
76. 作为维护者，我希望新 Agent 使用独立状态机，以便不继承公开搜索、即梦和合并阶段。
77. 作为维护者，我希望两个视频 Agent 只共享媒体检查、资产访问、原子文件写入和 SRT 校验等中立能力，以便减少重复而不耦合业务状态。
78. 作为维护者，我希望新 Agent 没有隐式自然语言路由，以便技能触发边界可以被可靠测试。
79. 作为维护者，我希望专属接口、运行状态和交付 schema 都可独立验证，以便后续迁移其他 Agent 时有清晰范式。
80. 作为维护者，我希望任何 blocked、draft、legacy、stale 或 incomplete 状态都明确显示，以便用户不会把未完成结果当成可用交付。

## Implementation Decisions

- 新增独立的 **Video Planning Entrypoint** `$tuolin-video-planner`，并禁止隐式调用；不修改 `$tuolin-video-workflow` 的用户流程。
- 使用独立 skill、独立状态机、独立运行 schema、独立确认阶段和独立终止状态；不将新流程实现为旧状态机的精简模式。
- 抽取可独立测试的共享深模块：媒体像素检查、已授权视频资产访问、原子文件写入、时间轴计算和 SRT 格式校验。共享模块不得包含趋势搜索、即梦或策划阶段语义。
- 建立 Agent-specific interface registry。每个注册接口声明自己的构建器、输出目录、读取策略和验证器；刷新事务按注册表构建并逐个验证。
- 本期注册并构建 **Video Planning Knowledge Interface**；保留旧共享接口作为明确的 legacy 兼容面，暂不迁移现有消费者。
- 视频策划接口拥有独立 manifest、interface revision、source knowledge revision、产品目录、允许的卡片投影、搜索索引、视频资产目录、视频档案详情、代表媒体映射、风险策略和验证摘要。
- 视频策划接口从正式知识源生成，不从其他 Agent 的下游接口读取或复制运行上下文。
- 知识库每次成功整理、更新、视频档案发布或复核写回，都必须调用统一刷新事务；若任何注册接口构建或验证失败，知识操作保持 incomplete。
- 新接口支持所有已正式发布且可外用或外用前复核的产品、应用场景、内容素材、证据、复核项和视频档案，并保留每张投影卡的内容指纹。
- `review_before_external` 内容只能进入草稿候选；存在产品身份、隐私、测试含义、权利或声明风险的素材不能进入可确认镜头方案。
- 视频资产访问采用三级检索：轻量目录筛选、候选档案详情与代表媒体、关键片段内的任务级受限预览。
- 源视频读取通过不透明资产 ID、产品范围、档案 revision、源 revision、允许操作、关键片段范围和撤销状态共同授权；不得接受任意 raw 路径。
- 新 Agent 创建独立 **Video Planning Run**，固定产品、平台声明、9:16 画幅、目标语言、目标时长和接口 revision。
- 访谈使用决策充分性而非固定问题表。核心决策包括受众、问题场景、观看理由、观众兴趣方向、核心记忆、期望行动、优先事实、排除内容和 AI 模拟边界。
- 从旧访谈契约中删除公开趋势证据与趋势机制；保留素材检查作为 Agent 内部证据，不把检查脚本交给用户。
- 每轮只允许一个待确认决策，并提供一个推荐及具体理由；已经在请求中明确的信息不得重复询问。
- 模型推理形成的钩子、叙事和镜头表达必须标记为策划推断；产品事实、应用和声明必须引用专属知识接口。
- 决策充分后直接生成 **Production-Ready Shot Plan**，不生成或确认中间总体策划。
- 镜头 schema 记录连续时间轴、镜头目的、可见动作、素材模式与来源、运镜、转场、剪辑提示、逐字旁白、风险和 AI 模拟标识。
- 所有来源视频片段在首版中强制为 visual-only，原声策略固定为不使用；声音设计、音乐和混音不进入 schema。
- 旁白按目标语言进行正常语速校验。每个镜头必须包含可读完的旁白，或明确标记为有意静默；整份方案不得完全没有旁白。
- 用户在确认前可以通过自然语言修改允许字段。每次修改必须重算连续时间轴、重新校验旁白并更新真实文件。
- **Shot Plan Confirmation** 一次确认镜头结构、素材和逐字旁白。确认后自动生成 **Narration-Derived SRT**，不得产生第二个 SRT 确认状态。
- SRT 文本必须逐字来自已确认旁白；任何 SRT 文案变化都转换成旁白修订并重新校验。
- 已交付运行可创建新的 **Planning Deliverable Revision**。每个确认版本不可变；新草稿不覆盖旧版，影响时间或旁白时使当前 SRT 失效。
- 每次运行固定专属接口 revision。最终确认前按引用卡指纹、视频档案 revision 和撤销状态进行实质变化检查；无关知识变化不阻止确认。
- 交付文件包括需求和访谈状态、修改记录、素材检查与预览、可读 Markdown 镜头方案、机器可读 JSON 镜头方案及确认后 SRT。
- 不创建供应商 Prompt、生成任务、额度估算、提交记录、下载结果、镜头生成文件、合并文件或发布内容。
- 用户界面每次需要确认时必须在 Codex 对话中展示足以决策的核心内容和素材预览，文件只用于审计与恢复。
- 项目状态和验收输出必须明确区分新 Agent 已隔离与旧消费者仍使用 legacy 共享接口的事实。

## Testing Decisions

- 测试只断言用户可观察的行为、持久化契约和安全边界，不锁定内部辅助函数、私有类名或实现顺序。
- 为 Agent-specific interface registry 编写契约测试：注册构建、独立输出、独立 revision、逐接口验证、失败传播和 legacy 迁移状态。
- 为知识写入联动刷新编写集成测试：产品整理、复核写回和视频档案发布完成后，新接口自动刷新且包含符合策略的本次写入。
- 为接口失败编写测试：专属接口缺卡、revision 不一致、校验异常时，上游操作不得报告完成。
- 为视频策划接口编写投影测试：只包含允许卡型与范围，支持多个正式产品，不暴露任意 raw 浏览能力，不读取其他 Agent 的上下文。
- 为视频资产三级读取编写测试：目录不返回完整档案或敏感转录；详情只为候选加载；代表媒体必须绑定 revision 和内容指纹。
- 为授权预览编写测试：拒绝任意 raw 路径、错误产品、过期档案、过期源文件、撤销资产、片段外时间点和超过候选预览上限的请求。
- 为运行创建编写参数化测试：仅接受显式 skill 流程、已发布产品、YouTube Shorts/TikTok、中文/英文、9:16 和 15–90 秒整数时长。
- 为无路由规则编写测试：普通“做视频”文本既不创建 planner run，也不自动转入完整视频工作流。
- 为访谈状态机编写测试：跳过已知答案、一次一个决策、推荐只确认当前项、事实修正需要知识验证、删除趋势字段、决策充分后直接进入镜头草稿。
- 为策划推断边界编写测试：允许创意推断进入计划，但没有正式卡片证据的产品参数、认证、应用或性能声明被拒绝。
- 为素材选择编写测试：真实视频优先于图片，图片优先于 AI 模拟；视频片段必须 visual-only；AI 模拟必须引用正式应用，具体产品必须引用真实产品图。
- 为风险门禁编写测试：`review_required` 候选可展示但不能确认；产品身份、隐私、测试含义、权利与声明风险会阻止最终方案；纯原声风险在 visual-only 策略下不阻止画面使用。
- 为镜头 schema 编写测试：时间轴连续、总时长准确、素材引用可追溯、每镜字段完整、无供应商字段、无屏幕 CTA 或字幕样式字段。
- 为旁白校验编写中英文参数化测试：正常语速可读完、过长旁白阻止确认、有意静默允许、整份方案不能完全无旁白。
- 为自然语言修订编写行为测试：删除、重排、改时长、换素材和改旁白实际修改文件并重新展示；保护字段不能被绕过。
- 为 SRT 编写测试：确认前不存在、确认后自动生成、逐字匹配旁白、时间码连续有效、没有独立确认状态、修改旁白后旧 SRT 失效。
- 为交付修订编写测试：旧确认版本不可变、新草稿有新编号、重新确认生成新版 SRT、旧版本仍可读取。
- 为接口 revision 固定编写测试：无关知识更新不改写运行；引用卡或视频档案发生实质变化时最终确认被阻止；撤销始终阻止确认。
- 为恢复流程编写测试：从任意访谈或草稿阶段恢复时只显示当前待处理决定，不重复已确认内容，也不进入旧视频工作流阶段。
- 为目录与打包编写测试：源 skill 与插件包都包含 `$tuolin-video-planner`、UI 元数据禁止隐式调用、脚本入口和模块导入在安装包中可用。
- 为旧 Agent 回归编写测试：原 `$tuolin-video-workflow` 的趋势搜索、即梦、下载和合并测试继续通过，证明本期没有改变其职责。
- 优先复用项目现有的知识接口、视频档案接口、真实片段、视频创作状态机、自然语言路由和包布局测试模式作为先例。
- 验收至少运行新增模块测试、所有视频与知识接口相关测试，以及完整测试套件；任何 legacy 失败或接口刷新未验证都阻止完成。

## Out of Scope

- 修改、删除或精简现有 `$tuolin-video-workflow`。
- 公开 YouTube 或 TikTok 趋势搜索、竞品扫描、播放量或热度研究。
- YouTube 横版、LinkedIn 视频、方形视频或其他画幅。
- 超过 90 秒的视频策划。
- 一项运行同时生成中英文两套旁白和时间轴。
- 字幕样式、安全区、字体、颜色、动画、烧录或屏幕 CTA 设计。
- 原视频声音、环境音、音乐、配音合成、TTS、混音或降噪。
- 即梦或其他供应商 Prompt、任务规划、额度估算、提交、查询、下载或重试。
- 生成视频镜头、提取交付级源片段、自动剪辑、合并、调色或发布。
- 将 AI 模拟包装为真实客户案例、测试或性能证据。
- 实现素材不足、缩短时长或有意重复审批分支；首版假设正式素材库充足，但仍校验实际选中素材。
- 自动路由未点名的视频请求，或询问用户应选择哪个视频 Agent。
- 在本期迁移所有旧 Agent 到独立知识接口。
- 生成后的镜头质量改进、二次生成或成片优化工作流。
- 将策划任务产生的判断写回正式知识库。

## Further Notes

- 本 PRD 采用 `CONTEXT.md` 中的 **Video Planning Consumer**、**Video Planning Knowledge Interface**、**Production-Ready Shot Plan**、**Confirmed Planning Narration**、**Narration-Derived SRT**、**Asset-First Video Planning Retrieval**、**Video Planning Run** 和 **Planning Deliverable Revision** 等规范术语。
- ADR 0023 记录 Agent-specific knowledge read interface 及自动刷新事务；ADR 0024 记录视频策划与视频生产分离，并取代 ADR 0001、ADR 0003 中“唯一视频入口”的部分。
- 本期接口隔离状态是“新 Agent 已独立，旧消费者仍为 legacy shared”，不是全项目迁移完成。
- 新 Agent 的完成条件是确认镜头方案与逐字旁白并生成校验通过的 SRT；任何 Dreamina、视频文件或发布结果都不是其完成证据。
- PRD 进入正常 triage 后再拆分实现切片；在 PRD 获得项目流程确认前不得开始开发。
